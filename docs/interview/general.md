# 공통 예상질문

자기소개, 경력, 강점, 협업, 실패, 학습 질문입니다. 경력 사실만 적었고, 본인 경험으로 채워야 하는 부분은 "채울 것" 상자로 남겼습니다.

## 자기소개 {#intro}

### 1분 자기소개를 해 주세요. {#self-intro}

??? answer "답 보기"
    순서는 "지금 하는 일 → 이전 경력 → 대표 성과 하나 → 지원 이유"입니다.

    현재 애자일소다에서 Data Engineer·RAG Engineer로 금융권 고객사의 금융 문서 기반 챗봇 지식검색(RAG) 인덱스·적재 파이프라인을 구축하고 있습니다(2026.09 ~ 진행중). 그 전에는 더존비즈온에서 Data Engineer로 2024.07부터 2025.08까지 스크래핑 수집 → Airflow 일 증분 적재 → REST API 조회 자동화, 국가별 법령문 적재, 감성 분석 대시보드 운영을 맡았습니다.

    대표 성과는 숫자 하나로 말합니다. 예: "요약·예상질문 벡터를 추가한 하이브리드 검색으로 바꿔말한 질문 검색을 16/20에서 18/20으로 올렸습니다."

    !!! note "채울 것"
        마지막 한 문장(이 회사에 지원한 이유, 앞으로 하고 싶은 일)을 본인 말로 적습니다.

### 지금 하는 일을 한 문장으로 설명해 주세요. {#current-role}

??? answer "답 보기"
    "금융 문서를 챗봇이 검색할 수 있게 파싱·청킹·색인하고, 검색 품질을 평가셋으로 재며 개선하는 파이프라인을 만들고 있습니다."

    이어서 물으면 범위를 넓힙니다. 문서 스키마 7종을 ES 인덱스 매핑으로 설계했고, Airflow(KubernetesExecutor) 기반 적재 배치를 설계했으며, 검색 → 답변 → 이중 판정 자동 평가 파이프라인으로 탐침 질문 96건을 자동 채점합니다.

## 경력 {#career-path}

### 더존비즈온에서 애자일소다로 옮긴 이유는 무엇인가요? {#why-moved}

??? answer "답 보기"
    말하는 틀은 "이전 회사에서 얻은 것 → 더 하고 싶었던 것 → 지금 회사에서 그것을 하고 있다는 근거"입니다.

    사실로 말할 수 있는 근거: 더존비즈온에서는 수집·적재·대시보드 운영 중심의 데이터 엔지니어링을 했고, 애자일소다에서는 역할이 Data Engineer에 RAG Engineer가 더해졌습니다.

    !!! note "채울 것"
        옮긴 실제 이유를 적습니다. 이전 회사에 대한 불만이 아니라 하고 싶은 일 중심으로 씁니다.

### 데이터 엔지니어링에서 RAG·LLM 쪽으로 넓힌 계기는요? {#de-to-rag}

??? answer "답 보기"
    틀은 "데이터 엔지니어링 경험이 RAG에서 어떻게 그대로 쓰였나 → 새로 배운 것"입니다.

    사실로 연결할 수 있는 지점: 더존비즈온의 데이터 수집 API · ETL 파이프라인에서 이미 LangChain·OpenAI로 초기 데이터와 파일에서 통합 데이터를 추출했고, 해외 법령 적재 · DB 관리에서 LangChain으로 법령 자동 번역과 참조 법령 탐색을 구현했습니다. 지금의 RAG 일도 문서 파싱, 적재 배치, 품질 검증이라는 데이터 엔지니어링 위에 있습니다.

    !!! note "채울 것"
        RAG 쪽으로 가고 싶다고 생각한 구체적인 계기(시점, 계기가 된 일)를 적습니다.

## 강점과 약점 {#strengths}

### 본인의 강점은 무엇인가요? {#strength}

??? answer "답 보기"
    강점 하나를 말하고, 경력 사실 두 개로 뒷받침합니다. 경력 기록에서 반복해서 보이는 패턴은 "바꾸기 전후를 숫자로 확인한다"입니다.

    근거로 쓸 수 있는 사실: 검색 평가셋 22문항으로 BM25·벡터·하이브리드의 Hit@5 비교를 자동화했고, bge-m3 벡터 양자화를 비교 평가해 bbq로 정확도 손실 없이 메모리를 1/7로 줄였습니다. 표 열 이름 오적재를 고친 뒤에는 표 질의 벡터 MRR 0.85 → 0.92로 효과를 확인했습니다.

    !!! note "채울 것"
        이 패턴을 본인이 강점으로 말하고 싶은지 확인하고, 다른 강점을 고른다면 그에 맞는 사실 두 개로 바꿉니다.

### 본인의 약점은 무엇인가요? {#weakness}

??? answer "답 보기"
    틀은 "실제 약점 → 그것 때문에 생긴 일 → 지금 보완하고 있는 방법"입니다. 직무에 치명적인 약점이나 장점을 위장한 약점은 피합니다.

    !!! note "채울 것"
        실제 약점과 보완 방법을 적습니다. 예상질문 탭에서 "경험이 운영·점검 수준"이라고 답한 기술(Kafka 등)을 약점과 연결할 수도 있습니다.

## 협업 {#teamwork}

### 팀원이나 고객사와 의견이 달랐던 경험을 말해 주세요. {#conflict}

??? answer "답 보기"
    틀은 STAR입니다. 상황(누구와 무엇이 달랐나) → 과제(무엇을 정해야 했나) → 행동(근거를 어떻게 모으고 어떻게 합의했나) → 결과(무엇으로 결정됐고 이후 어땠나). 상대를 깎아내리지 않고, 결정 근거를 데이터나 기준으로 말합니다.

    !!! note "채울 것"
        애자일소다(금융권 고객사 프로젝트) 또는 더존비즈온에서 실제로 있었던 사례 하나를 적습니다.

## 실패와 어려움 {#failure}

### 가장 어려웠던 기술 문제와 해결 과정을 말해 주세요. {#hardest-problem}

??? answer "답 보기"
    틀은 "증상 → 원인을 어떻게 좁혔나 → 조치 → 숫자로 된 결과 → 다시 생기지 않게 한 것"입니다.

    경력 기록에 있는 후보:

    - 수천 회 외부 LLM 호출 배치가 중간 DNS 오류로 중단 → 호출 결과를 해시 키 jsonl 캐시로 저장해 완료분 재사용 → 재실행 추가 호출 0회, 재과금 없음.
    - 표 열 이름이 `----`로 오적재(7청크) → PDF 파서의 구분선 오인 확인, 구분선 행 제거 후 재적재 → 오류 청크 7 → 0, 표 질의 벡터 MRR 0.85 → 0.92.
    - 대형 표 분할 시 청크 크기 초과(최대 2,932자) → 긴 머리글 반복 중단, 각주 별도 청크 → 초과 청크 183개 → 0개.

    !!! note "채울 것"
        하나를 고르고, "원인을 어떻게 좁혔나"를 실제 과정대로 적습니다. 이 부분은 경력 기록에 없습니다.

### 실패했던 경험과 거기서 배운 것을 말해 주세요. {#failure-lesson}

??? answer "답 보기"
    "어려웠던 문제"와 달리 내 판단이 틀렸던 경험을 묻는 질문입니다. 틀은 "무엇을 잘못 판단했나 → 그 결과 → 어떻게 수습했나 → 이후 바꾼 습관"입니다. 수습만 하고 끝난 이야기보다 이후 바꾼 습관이 있는 이야기가 좋습니다.

    !!! note "채울 것"
        실제 실패 사례 하나와 그 뒤 바뀐 작업 방식을 적습니다.

## 학습 {#learning}

### 새로운 기술은 어떻게 학습하나요? {#how-learn}

??? answer "답 보기"
    틀은 "학습 방법 → 최근 실제로 배운 기술 하나 → 그것을 일에 적용한 결과"입니다.

    적용 사례로 쓸 수 있는 사실: 개인 프로젝트로 Smart Factory Data Agent(NL2SQL), DW 기반 이벤트 로그 ELT Pipeline(SCD Type 2), User Behavior Data Warehouse(Airflow·품질 검사), AI 기반 숏폼 영상 생성 시스템(Gemini 영상 분석)을 만들었습니다.

    !!! note "채울 것"
        실제 학습 습관(문서, 실습 저장소, 이 사이트 같은 정리 방식)과, 개인 프로젝트로 배운 것을 업무에 쓴 사례가 있으면 적습니다.
